# AI FACE 使用者與社群流程

<p align="center">
  <a href="./USER-FLOWS.md">English</a> ·
  <strong>繁體中文</strong>
</p>

本文件是一般使用者、角色創作者、投票者與維護者如何在 AI FACE 與
AI FACE Personas 之間行動的正式流程依據。

## 狀態用語

- **目前可用**：Phase 6 內部試用版已經具備。
- **規劃中**：公開版預定體驗，目前尚未上線。
- **需要 GitHub**：只有會改變公開社群角色庫的行為才需要。

## 兩個專案的責任

| 專案 | 責任 |
| --- | --- |
| [AI FACE](https://github.com/page5888/AI-FACE) | Chrome 擴充功能、內建角色、本機匯入、ChatGPT Overlay、動畫、語音反應、版面與置頂模式。 |
| [AI FACE Personas](https://github.com/page5888/AI-FACE-Personas) | 經審查的公開角色包、投稿規則、版權審查、社群投票與目錄歷史。 |

規劃中的公開網站是一般人的入口。使用者不需要先理解 repository、Manifest、
Pull Request 或 Sprite Sheet，就能知道產品是什麼以及如何開始使用。

## 1. 一般使用者流程

### 目前可用：內部試用版

```text
建置並以開發人員模式載入擴充功能
→ 開啟或重新整理 ChatGPT
→ Haruna 自動出現
→ 開啟 AI FACE Popup
→ 選擇九個內建角色之一，或匯入一個本機自訂角色
→ 需要時由使用者主動開始語音同步
→ 移動、縮放、鎖定、隱藏、重設或開啟置頂模式
```

目前仍需使用開發人員模式安裝，尚未提供 Chrome Web Store 一鍵安裝。

### 規劃中：公開版無摩擦流程

```text
開啟 AI FACE 官網
→ 點擊「安裝 AI FACE」
→ 從 Chrome Web Store 安裝
→ 開啟 ChatGPT
→ 選擇角色
→ 立即使用
```

一般使用者不應被要求擁有 GitHub 帳號、下載原始碼、安裝 Node.js、理解
Sprite Sheet 或參加投票，才能使用已核准的角色。

## 2. 個人本機角色流程

這條流程只讓角色擁有者自己使用，不會公開檔案。

```text
建立或取得自己有權使用的圖片
→ 在 AI FACE 開啟「選擇角色」
→ 選擇支援的匯入模式
→ AI FACE 在本機驗證、整理並保存
→ 在 ChatGPT 使用角色
```

- 不需要 GitHub 帳號。
- 圖片保存在 Chrome 擴充功能的本機儲存空間。
- 本機匯入不等於投稿到公開角色庫。
- 使用者仍須自行確認有權使用該圖片。

## 3. 瀏覽已核准的社群角色

**目前狀態：** 經審查的目錄位於本倉庫，而且刻意從空白開始。

**規劃中的網站體驗：**

```text
開啟「瀏覽角色」
→ 預覽已核准角色
→ 查看創作者與授權資訊
→ 在 AI FACE 新增或選擇相容角色
```

瀏覽及使用已核准角色不應要求 GitHub 登入。公開網站只能展示正式核准的目錄
資料，不得直接顯示尚在審查中的投稿檔案。

## 4. 投稿到公開角色庫

公開散布的門檻必須比個人本機使用更嚴格。

```text
建立原創角色
→ 確認所有權、再散布權與聲明授權
→ 準備 persona.json、preview.png、spritesheet.png
→ Fork AI-FACE-Personas
→ 執行 npm test 與 npm run validate
→ 建立 Pull Request 並完成所有權利聲明
→ 自動技術驗證
→ 維護者版權與安全初審
→ 社群投票
→ 維護者最終核准
→ 合併到正式角色目錄
```

**只有公開投稿、審查與投票需要 GitHub。** 一般使用產品或本機匯入角色都不需要。

## 5. 社群投票與核准

投票衡量的是社群興趣，不能證明投稿者擁有著作權。

```text
Pull Request 通過自動驗證
→ 維護者確認具備公開審查資格
→ 維護者建立連結到該 PR 的 GitHub Discussions 投票
→ 社群查看預覽、署名與聲明授權
→ 投票依公告期限結束
→ 維護者把結果記錄在 PR
→ 維護者核准、要求修改或拒絕
```

建議狀態：

- `rights-review`：正在確認權利與再散布資格。
- `vote-open`：社群投票進行中。
- `community-approved`：票選通過，仍等待維護者最終審查。
- `changes-requested`：需要修正技術或視覺問題。
- `rejected-copyright`：因權利疑慮拒絕。
- `accepted`：已合併至正式公開目錄。

無論票數多高，都不能推翻可信的版權、商標、隱私或安全疑慮。投票不得自動合併
Pull Request。

## 6. 版權檢舉與移除

```text
檢舉者指出精確的公開檔案
→ 使用版權疑慮 Issue 表單，且不公開私人資料
→ 疑慮可信時，維護者暫停投票或散布
→ 檢查角色資料、署名、公開證據與 repository 歷史
→ 確認無誤、要求修正、拒絕或移除
→ 正式法律通知仍使用 GitHub 官方程序
```

請勿在公開 Issue 上傳私人合約、身分文件、地址、電話、原始照片或其他敏感證據。

## 7. 摩擦邊界

| 目標 | 需要 GitHub 帳號？ | 需要 AI FACE 後端？ |
| --- | --- | --- |
| 安裝與使用 AI FACE | 否 | 否 |
| 選擇已核准角色 | 否 | 否 |
| 匯入個人本機角色 | 否 | 否 |
| 瀏覽規劃中的公開角色網站 | 否 | 否 |
| 投稿到公開角色庫 | 是 | 否 |
| 在 GitHub Discussions 階段投票 | 是 | 否 |
| 提出非正式 repository 版權疑慮 | 是 | 否 |

本專案刻意讓一般使用保持無摩擦，同時讓公開散布具備可審查、可追溯的紀錄。

## 8. 停止條件

角色在以下情況不得進入或繼續留在公開目錄：

- 所有權或再散布權不清楚；
- 設計重現可辨識的第三方智慧財產；
- 缺少必要檔案或聲明；
- 自動驗證失敗；
- 存在可信但尚未解決的權利或安全疑慮；
- 維護者尚未最終核准。
